# SlimSpot

Minimum-RAM native Spotify client for Windows and Linux (x64; Linux since 2026-10-20). Rust + Freya (Skia, software renderer) + librespot. MIT licensed (`LICENSE`); `README.md` is the user-facing doc.
Spotify ToS concerns are accepted by the owner. The GitHub repo is **public** (owner's decision, 2026-10-05).

## Goal & how it's judged
- RAM is the deciding metric. Measure **Private bytes** of the installed build (`fast` profile; same RAM as the LTO release, measured 2026-10-04) while a track plays, sampled 3× over 10 s
  (`Get-Process slimspot`), after opening a playlist and scrolling. Working Set includes shared DLLs and is secondary.
- Budget: **50 MB private** while playing (owner's limit, set 2026-10-05); small per-feature growth is acceptable within it.
- Reference point (2026-10-20, Freya UI, `fast` build): 31.5 MB private at startup idle; 29.6 / 30.2 / 32.9 MB while playing after opening and scrolling Liked Songs (817 songs). The Slint UI it replaced measured 18.6 MB at startup idle (2026-10-08) and 19.7 MB on 2026-10-20; most of the difference is Skia and its embedded ICU data.
- Older reference points (2026-10-05, after the feature batch): ~15.7 MB private at startup idle, 22.7 MB while playing after opening and scrolling a 790-song playlist. Startup was 11.5 MB at the start of that day; search tabs/podcasts/popups added ~3.5 MB (podcast loading ~0.6 MB of it, the rest not isolated). Spotifast (egui) claims 100–250 MB; a Tauri app measured 194 MB.
- Any new feature reports its RAM delta. No GPU renderer, no webview, no browser engine.
- Linux RAM: compare `Private_Dirty` from `/proc/<pid>/smaps_rollup` with Windows Private Bytes. Linux also counts the binary's and GTK's file-backed code pages as `Private_Clean` (~40 MB, reclaimable), which Windows doesn't. Reference (2026-10-20, WSL Arch, `fast`, idle after Home): 18.6 MB `Private_Dirty`, 59 MB private in all.

## Commands
- Test: `cargo test` (unit tests live next to the code they test)
- Day-to-day build: `cargo build --profile fast` → `target/fast/slimspot.exe` (~25–40 s after a change: no LTO, 16 codegen units, incremental)
- Release build: `cargo build --release` → `target/release/slimspot.exe` (full LTO, ~4 min after any change since it re-optimises the whole program on one thread; 0.5 MB smaller exe, no RAM difference)
- Install/update for daily use: `.\install.ps1` (`fast` build, copy to `%LOCALAPPDATA%\Programs\SlimSpot\SlimSpot.exe`, Start menu shortcut, autostart on first install). `-Release` (LTO build), `-NoAutostart`, `-Uninstall`. It stops a running SlimSpot first.
- Linux: `./install.sh` (builds `fast` unless a prebuilt `slimspot` sits next to it, copies to `~/.local/bin/slimspot`, menu entry + icon in `~/.local/share`, autostart entry on first install). `--release`, `--no-autostart`, `--uninstall`. Linux builds need `clang` (Skia's bindgen) and alsa-lib, gtk3, libayatana-appindicator, xdotool (libxdo). Build env used here: WSL `archlinux` (WSLg shows the window and has PulseAudio; ALSA reaches it via alsa-plugins and `pcm.!default { type pulse }`).
- Release: bump `version` in `Cargo.toml` (the update check compares against it), build with `-Release`, zip `SlimSpot.exe`, `LICENSE`, `OFL.txt`, `THIRD-PARTY-NOTICES.txt`, `README.md` as `SlimSpot-X.Y.Z-windows-x64.zip`, sign it with `openssl dgst -sha256 -sign <private key> -out SlimSpot-X.Y.Z-windows-x64.zip.sig SlimSpot-X.Y.Z-windows-x64.zip`, for Linux build `cargo build --release` on Arch (WSL) and pack `slimspot`, `slimspot.png` (from `assets/icon-256.png`), `install.sh`, `LICENSE`, `OFL.txt`, `THIRD-PARTY-NOTICES.txt`, `README.md` in a `SlimSpot-X.Y.Z/` folder as `SlimSpot-X.Y.Z-linux-x64.tar.gz`, signed the same way; publish all of them on a `vX.Y.Z` GitHub release (a release without the `.sig` is never offered to signed builds). Running copies offer it via "Update to vX" (a private repo would answer the anonymous API call with 404).
- Update signing key (once): `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out slimspot-update.pem` (keep it outside the repo, backed up; never commit it), `openssl pkey -in slimspot-update.pem -pubout -out assets/update-public-key.pem` (committed). Until that file has a key, `fast`/release builds refuse to compile. Losing the private key means users can only move to a new key by installing a release by hand.
- Runtime files: `%APPDATA%\SlimSpot\` (Linux: `$XDG_CONFIG_HOME/SlimSpot`, default `~/.config/SlimSpot`) — `credentials.json` (librespot), `web_refresh_token`, `settings.json`, `library.json` (sidebar cache), `slimspot.log` (warn/error only), `audio/` cache
- Web API client id, first that is set: env `SLIMSPOT_WEB_CLIENT_ID`, Settings → Spotify app (`settings.json` `web_client_id`, validated as 32 hex), the client id the saved token belongs to, else the public app shared by ncspot/spotify-player/Spotifast (Spotifast's model: optional personal id over a shared default). Redirect `http://127.0.0.1:8989/login`. A new id takes effect on restart (one browser consent); clearing it also deletes `web_refresh_token`. If refreshing the saved token answers `invalid_client` (the personal app was deleted), the shared app is used, the id is cleared from Settings and the status line says so; an env var naming it must be removed by hand, since a dead id can't be detected before the browser consent (see constraints). A quota 429 on the personal app (Retry-After over 30 s) switches that run to the shared app (`WebApi::use_shared_app`; its token lives in `web_refresh_token.shared`, so one browser consent the first time) and the status line says so; the next start tries the personal app again.

## Architecture (`src/`)
| Module | Responsibility |
|---|---|
| `main.rs` | Starts the backend thread (tokio runtime shared with the UI thread), single instance, `--tray`, then `ui::run` |
| `ui.rs` | The Freya UI: `UiUpdate` (everything the backend shows), the `Model` it updates, all screens and popups, tray, shortcuts, design tokens |
| `player.rs` | Backend tokio thread: login, Spotify Connect device (Spirc), command/event loop, reconnect. Talks to the UI only through `ui::Ui` |
| `web.rs` | Spotify Web API (separate OAuth grant): search (all + per-type tabs, paged), queue (view, add), recently played, liked checks, playlists (create, edit name/description, cover upload, remove, add/remove/reorder tracks), Liked Songs, albums, artist release groups (paged), newest release, saved albums, followed artists, saved podcasts + episodes (paged), saved episodes ("Your Episodes"), like/unlike, devices, transfer |
| `covers.rs` | Downloads cover images the UI asks for (instantiated rows only) and sends the encoded bytes; the UI keeps at most 300 and Freya decodes them at drawn size. Cover upload as 500 px JPEG |
| `settings.rs` | `settings.json`: volume, shuffle, repeat, quality, normalize, last session, last-opened times of library entries, EQ, low API mode, compact list, sidebar width (`sidebar_w`, 80 = collapsed), Home's new release (per day) |
| `media_keys.rs` | Windows SystemMediaTransportControls (windows-only) |
| `*_linux.rs` | Linux counterparts picked with `#[path]` in `main.rs`, same API: `instance_linux` (Unix socket in `$XDG_RUNTIME_DIR`), `media_keys_linux` (MPRIS on the session bus via zbus), `autostart_linux` (`~/.config/autostart/slimspot.desktop`), `dialog_linux` (rfd: portal/GTK) |
| `targz.rs` | Minimal `.tar.gz` reader (gzip via `miniz_oxide`, ustar) for the Linux update archive (non-Windows only) |
| `logger.rs` | File logger for warn/error, including librespot's |
| `instance.rs` | Single instance via a named event; a second launch wakes the running window; title bar colors via DWM (windows-only) |
| `lyrics.rs` | Lyrics via librespot `spclient().get_lyrics` (Spotify's color-lyrics, no Web API), parsing and current-line lookup |
| `nav.rs` | Back/forward history of whole pages (rows included, 20 deep) |
| `clipboard.rs` | Plain-text clipboard (Win32; Linux: Freya's copypasta clipboard, UI thread only, so the backend's "Copy link" goes through `UiUpdate::CopyText`): `open.spotify.com` links for "Copy link"/Ctrl+C, reading pasted song links for Ctrl+V |
| `dialog.rs` | Native Open dialog (IFileOpenDialog) for picking a playlist cover (windows-only) |
| `zip.rs` | Minimal zip reader (stored + deflate via `miniz_oxide`) for the update archive (Windows only) |
| `eq.rs` | 10-band EQ, preamp and balance: `EqSink` wraps librespot's sink, settings via a static (`eq::set`) |
| `update.rs` | GitHub Releases update: check at startup, download, swap the exe (`.old`), relaunch with `--wait-pid` |
| `taskbar.rs` | Taskbar thumbnail buttons (prev/play-pause/next) and progress via ITaskbarList3 (windows-only) |
| `autostart.rs` | "Start with Windows": HKCU `Run` value `"<exe>" --tray` (windows-only) |
| `build.rs` | Embeds `assets/icon.ico` into the exe via the Windows SDK's `rc.exe` (skipped with a warning if missing) |

## Confirmed decisions
- **Spirc owns playback state** (queue, shuffle, repeat, track advance). Local actions become Spirc calls; there is no local queue. Playlists/albums/artists/Liked Songs play as Spotify contexts; search results as a track list.
- **Two OAuth grants**: librespot playback (Spotify desktop client id, port 8898) and Web API (own app, port 8989). The playback token is rejected/rate-limited on api.spotify.com.
- **Quality/normalisation are per-Player**: changing them restarts the Connect device and resumes at the same position.
- **Volume**: slider drags set the local mixer only; Spirc (and thus Spotify) gets one update on release. Per-step Spirc updates hit 429 and stalled the loop.
- Spotify Connect device name: `SlimSpot`, type Computer.
- **Close hides to the tray**, playback continues; real quit is tray "Quit" or `Ctrl+Q` (saves the session, shuts Spirc down so no stale device lingers). The event loop runs via `run_event_loop_until_quit`, not `app.run()`.
- **Last session is shown paused and loaded on the first Play**, never at startup: loading would make SlimSpot the active device and pause the phone. Saved on track change, pause and quit (`settings.json` → `last`).
- **Licensing for release**: own code MIT; Freya MIT; Skia (BSD-3) and its embedded ICU data (Unicode License V3) are compiled into the exe, so their notices ship in `THIRD-PARTY-NOTICES.txt` (in the release zip); Poppins under OFL (`assets/fonts/OFL.txt`). The Slint badge went with Slint (2026-10-20).
- **Icons**: `assets/icon.svg` is the source; `icon-64.png`/`icon-256.png` are rendered from it (headless Edge, 64 downscaled from 256) and embedded with `include_bytes!`: the tray icon (decoded with `image`) and the window icon (`LaunchConfig::window_icon`).
- **Keyboard**: one global key handler (`ui::on_key`). Spotifast's set: Shift+arrows seek 10 s, M mute (restores the previous volume), B like, Q queue, `/` search, Ctrl+B sidebar, Ctrl+H Home, Ctrl+, Settings, `?` list, Up/Down move a row cursor (Shift extends), Enter plays it, Ctrl+Y lyrics, Ctrl+F find in page. Ctrl+L stays the global search (Spotifast uses it for Liked Songs). Unmodified letters only fire while the search box doesn't have focus (its `AccessibilityId`).
- **Lyrics**: fetched per track change, not cached on disk; shown in place of the page (`Ctrl+Y`, mic button). Fixed line height so the sung line is placed arithmetically; highlighted on the 500 ms position tick. Like Spotifast: clicking a synced line seeks there; a scroll the follow logic didn't make stops following (scroll position vs the last one it set) and a "Follow" chip resumes it; "Full screen" makes the window full screen with the sidebar and right panel hidden; the chip, Esc, leaving lyrics or a page change leave it.
- **Radio** works for tracks, playlists, albums and artists (`spotify:station:<kind>:<id>`, all verified 2026-10-05; header radio icon on those pages, "Start radio" in their row menu). A radio page can be saved as a private playlist ("Save as playlist": create + `add_tracks`, 100 URIs per request). Original note: `spclient().get_context("spotify:station:track:<id>")` is resolved once and its 50 tracks are shown and played as a track list. Spotify reshuffles a station on every resolve, so loading the station context into Spirc would play a different order than the list shown.
- **Track metadata** (radio, artist popular tracks, Spotify-made playlists) comes from librespot `Track::get` in `player::track_items`, at most 8 lookups in flight. All 50 radio lookups at once left private RAM ~10 MB higher for good (15.9 -> 26 MB); capped, a radio costs ~2.5 MB (2026-10-04).
- **Design** (owner's call 2026-10-20, replacing the Spotifast look and its themes): one dark theme (design tokens at the top of `ui.rs`: neutral black surfaces, `#1ed760` accent only on actions, Poppins SemiBold headings, 8 px grid, 12 px panels, 6–8 px covers), page headers tinted by the playing cover, 150 ms hover fades and a 250 ms fade/slide when a page opens. Icons are 24×24 SVG path strings drawn with `SvgViewer`. More themes may come later. Spotify's logo and icon artwork are not copied.
- **Themes**: none for now (one theme; see Design). Freya's own component theme (inputs, menus, sliders, popups) is its dark theme recolored with the design tokens (`ui::theme`).
- **Paused audio stays open**: librespot's rodio sink only pauses (`rodio_sink.pause()`), the output stream lives on. Measured 2026-10-05: 16 ms CPU per 10 s paused, private 17.6 MB vs 14.0 MB before the first play; not worth a custom sink. Whether the open stream blocks system sleep is unverified (`powercfg /requests` needs admin).
- **Font**: Poppins Regular/SemiBold (SIL OFL, `assets/fonts/`, license in `OFL.txt`) embedded with `LaunchConfig::with_font` and set as the default font.
- **Title bar**: kept native (snap, resize) but colored through DWM (`DWMWA_CAPTION_COLOR`/`TEXT_COLOR`/`BORDER_COLOR`, Windows 11) to blend into the base color (`instance::dark_title_bar`, from the window creation hook). A frameless window would need its own move/snap handling.
- **Renderer: software only** (Freya built with `default-features = false`, `winit` + `tray`; `RendererPreference::Software`). Freya's GPU renderer measured 172 MB private in the prototype (2026-10-20), so it isn't compiled in and the GPU setting is gone. Slint and Freya can't share a Cargo graph: both link Skia (`links = "skia"`), which Cargo rejects even for optional dependencies.
- **EQ**: real, not decorative: RBJ peaking biquads (Q 1) at Winamp's 10 bands, ±12 dB, plus preamp and balance, in `EqSink` around the rodio sink; bypassed when off and flat. Settings → Playback: on/off, Winamp's built-in presets, preamp + 10 vertical `EqBand` sliders (double-click resets one); they apply at once (`eq::set`) and are saved on release (`Command::Eq`). Balance is kept in `settings.json` but has no control since the skin went.
- **Right panel tabs** (Spotifast's Queue/Recent panel): Now playing, Queue (`Ctrl+U`, Q, bar icon) and Recent share the right panel (`Model.side_tab`, rows in `side_rows`). Spirc keeps its queue private, so Queue comes from Web API `/me/player/queue` (`Command::Queue`, reloaded when the tab opens, not on track change); Recent reuses Home's recently played (`Command::Recent`). A Recent row plays that track alone. While the panel is open, Home shows two tiles per row.
- **Search "Show more"**: a search page with a further page ends with a `slimspot:more` row; clicking it appends the next `offset` page to the same history entry (`nav::History::current_mut`). Rows with a `slimspot:` URI have no context menu.
- **Search tabs** (All/Songs/Albums/Artists/Playlists, `Page.search`): All mixes artists, albums and tracks (pages tracks while a full 10 came back); the type tabs page by the response's `next`, since playlist results contain nulls (2 of 10 seen 2026-10-05). Switching tabs replaces the search page in history instead of pushing one.
- **Podcasts**: saved shows join the sidebar ("Podcasts" filter, save/remove like albums); a show page lists its newest 50 episodes and plays as the `spotify:show:` context (verified to play, 2026-10-05). `is_playable` covers tracks and episodes.
- **Playlist create/edit popup**: "+" asks for name and description first (prefilled "My Playlist #N"; nothing is created on cancel), unlike Spotify, which creates at once (checked 2026-10-05). The pencil on own playlists opens the same popup for name, description and "Change cover..." (JPEG/PNG → 500 px square JPEG, base64, `PUT /playlists/{id}/images`, scope `ugc-image-upload`). Playlist pages show the description (HTML stripped) after the kind label.
- **Podcast publisher** comes from librespot `Show::get` (`player::show_publisher`): this app's `/shows/{id}` and `/me/shows` carry no `publisher` field (seen 2026-10-05).
- **Cover refresh after upload**: Spotify serves the new image under a new URL a few seconds later; `Command::RefreshCover` polls `/playlists/{id}?fields=images` every 3 s, up to 10 times, from a timer task (the command loop keeps running), then updates sidebar and header.
- **Your Episodes** (`web::YOUR_EPISODES`, below Liked Songs): `/me/episodes` rows named by their show; it has no Spotify context to load, so it plays as a track list (verified 2026-10-05). Listed under the "Podcasts" filter.
- **Show pages page their episodes**: 50 per page with "Show more" (`Page.more` kind `"episode"`, the show URI in place of the query).
- **Playlists open on their first page**: the first 50 songs show at once (`list_tracks_first`), the rest is fetched after and appended in place (`UiUpdate::AppendTracks`, so covers and scroll stay); the description loads after the page. Liked Songs (817 songs): 3.8 s to the page before, ~0.4 s after (2026-10-20). The command loop still waits for the rest before the next command.
- **Add songs** (own playlists): "+" next to the pencil, or the "Let's find something for your playlist" chip on an empty one, opens a popup that searches tracks (`Command::AddSearch`) and adds a result to the open playlist (`Command::AddToPage`), appending the row in place. Popup text fields focus themselves (`auto_focus`).
- **Library sort** chip cycles library order / Recents / A-Z. Recents uses `Settings.opened` (URI -> last opened, Unix seconds), written when a library entry is opened; never-opened entries keep library order after the rest. A library change (create, rename, remove) resets filter and sort.
- **Artist pages have tabs** (Popular, Albums, Singles, Compilations, Appears On, About; `Page.search` holds the artist URI and tab, like search). Popular is librespot top tracks; the release tabs are Web API `include_groups=<group>` pages with "Show more"; About is the librespot biography (`artist_bio`, HTML stripped). "Fans also like" is not possible: librespot's `Artist.related` comes back empty and the Web API endpoint is closed (checked 2026-10-05).
- **Album pages**: the kind line shows full release date, label and copyright; "More by this artist" opens the first artist on the Albums tab (`open_tab`). Header texts have `min-width: 0` so long titles elide instead of pushing the buttons out.
- **Credits** ("View credits" on tracks): spclient `GET /track-credits-view/v0/experimental/<id>/credits` (JSON, verified 2026-10-05), shown as "Role: names" lines in a popup.
- **Now-playing panel**: lyrics preview (sung line + next two, from the loaded lyrics) and the first 400 characters of the artist's biography, fetched once per artist change.
- **Page shuffle** button next to the page play button mirrors the player's shuffle state.
- **Home tiles** share their cover with the sidebar row of the same entry: covers are kept by URL, so the same image is fetched and decoded once.
- **Home tiles**: up to 8 library entries (most recently opened first) in two columns (`quick-top` left, `quick-bottom` right) under the greeting; the first can be "New release · <artist>": the newest album/single of the 10 most recently opened followed artists, if released within 60 days (`days_from_date`), looked up once per run.
- **Removing from the library asks first** (confirm popup); for an own playlist it is Spotify's delete.
- **Playlist editing**: "Add to playlist" offers only the user's own playlists (`web::Item.artist_uri` holds a playlist's owner URI, compared with `spotify:user:<username>`). "Remove from this playlist" shows only on such a page (`Page.editable`) and removes every occurrence of the track.
- **Go to playing** (click the now-playing title): opens the context the track was started from in this window and scrolls the list to it (`UiUpdate::Reveal`, the list's scroll controller). Tracks started elsewhere have no known context.
- **Page header**: a kind label ("Playlist", "Album", ...; `Page.kind`) above the title. Track rows show a play arrow on hover and equalizer bars while playing, over the cover.
- **Scroll**: opening a page or going back/forward remounts the page (`Model.page_gen`), so it starts at the top; pages that change in place ("Show more", removing a row) keep their scroll. "Show more" drops tracks already on the page, since later search pages repeat earlier hits.
- **Home** (opened at startup and by Home/Ctrl+H) is one scrolling page: a greeting by the local hour (`greeting`, `GetLocalTime`), the tiles, a "Recently played" shelf of up to 10 album cards (albums of the recently played tracks, 160 px covers, ~1 MB) and the recent tracks themselves (`/me/player/recently-played`). The history's `context` isn't used for the shelf: it names no playlist, and all 50 entries came from one Spotify-made playlist (checked 2026-10-08). Spotify's own "Made for you" shelf is not reachable: Web API search for "Daily Mix"/"Discover Weekly" only finds other users' copies (Spotifast's approach, verified 2026-10-04). Opening a Spotify-made playlist falls back to librespot `get_context` when the Web API refuses it.
- **Track rows** carry `duration_ms` and `liked`. Liked marks are fetched after a page is on screen, 200 rows per batch (`mark_liked`, 40 URIs per request); the UI asks for the next batch (`Command::CheckLikedMore`) when the list scrolls within 20 rows of the checked ones. Rows of playlists/albums/radio/queue are numbered; the header shows "N songs, about X hr" and an accent play button that starts the page from its first track. Hovering a row shows "..." which opens the same row menu; the playing row shows stepped equalizer bars (300 ms steps, to keep CPU low).
- **Library filters** (Playlists/Albums/Artists/Podcasts + name filter, sort chip next to the filter field) filter the loaded sidebar rows in the backend (`Command::FilterLibrary`); no request.
- **Library**: "+" creates a private playlist through the create popup and opens it; the pencil next to an own playlist's title edits it; "Remove from Your Library" in a sidebar row's menu unfollows (Spotify's delete for own playlists). Changes update the sidebar and "Add to playlist" targets without a reload. The sort chip orders the sidebar; there is no "All" chip, clicking the chosen filter clears it.
- **Now playing panel** (bar button) shows the playing track's 300 px cover; **page headers** of playlists/albums show the page's cover. Rows keep only the smallest cover URL, so `covers::larger_cover` rewrites it to the 300 px variant (album image ids, mosaic paths).
- **Mini player** (bar button): only the player bar is rendered; the window shrinks to 860x96 and stays on top, and the previous size is restored.
- **Sleep timer** (settings): 15/30/60 min pauses via a `sleep_until` branch in the backend loop; "End of track" pauses on the next `TrackChanged`.
- **Queue rows**: clicking one skips ahead with `Spirc::next` (`Command::SkipTo`; the playing context carries on) and drops the passed rows locally (`queue_rows`), since `/me/player/queue` lags right after a skip.
- **Dropped sessions**: Spotify sometimes closes the session just as a track loads; the audio key request times out and the still-encrypted data fails to decode ("end of stream"), which ends the Connect loop. After the reconnect, a track asked for within the last 30 s (`RETRY_LOAD_WINDOW`) is loaded again and played. `last_load` records the requested track and position, because the session can drop before `TrackChanged`: the retry (and Play with nothing started) loads that track, not the previous `now_uri`; with nothing at all to play, Play says so instead of doing nothing. Play on a device that isn't active (after a reconnect; Spirc ignores `play` then) loads the current track at its position instead (`paused_here` tells the two apart).
- **Settings page** ("Settings" pill in the top bar or Ctrl+,): covers the main panel (`Model.show_settings`), not a `nav::History` page; Esc and any page change close it. Bold section headings (Audio quality, Playback, Display, Spotify API, Startup, Updates), label + description on the left, control on the right (`setting_row`). The Slint version's settings search field was not ported.
- **Settings page and popups** use Freya's components (`Switch`, `Slider`, `Popup`, `Input`) in the recolored dark theme.
- **Multi-selection** (Spotifast's): `Model.selected` (row indexes). Ctrl+click toggles, Shift+click extends from the anchor (Freya's pointer events carry no modifiers, so Ctrl/Shift are read with `GetKeyState`), Ctrl+A selects all. Ctrl+C copies `open.spotify.com` links, Ctrl+V adds pasted song links to the open own playlist (`Command::AddUris`, rows looked up with `track_items`), Ctrl+X copies and removes, Delete removes (`Command::RemoveUris`, one request per song). No duplicate check before adding (Spotifast asks).
- **Drag to the sidebar**: any track row can be dragged (Freya `DragZone`); dropped on an own playlist or Liked Songs in the sidebar (`DropZone`) it is added there, with the selection if the row belongs to it. Reordering stays limited to own, unsorted, unfiltered playlists: drop one row on another (`Command::MoveRow`).
- **Sidebar rows**: double-click or the cover's hover play button plays the entry without opening it.
- **Compact track list** (Settings → Display, `settings.json` `compact`): one-line 36 px rows without covers; no cover is fetched in that mode.
- **Winamp skin mode was removed** (owner's call, 2026-10-08); its EQ moved to Settings → Playback. The zip reader stayed for updates (`zip.rs`).
- **Sidebar width**: dragging the gap between the sidebar and the page resizes it (220–480 px, `SidebarHandle`), saved on release (`Command::SidebarWidth`). Below 160 px, or the library icon next to "Your Library", collapses it to 80 px (covers only, icon-only Home/Search, library icon + "+"), like Spotify; the library icon opens it again at the last width.
- **Page header** size: 160 px cover, 44 px title (30 px past 24 characters); kind label, title, description, then the size line.
- **Client ID field** (Settings → Spotify API) is masked like a password; the eye next to it (outside the `Input`, which swallows presses inside it) shows it.
- **Status messages** (loading, errors, "Signed in") show as a pill at the bottom of the page for 7 s (`Toast`, `TOAST_SECS`); the page's size ("50 songs, 2 hr 42 min", `page_summary`) is a line in the page header (`UiUpdate::Summary`), reset on page change and play/pause. The startup message doesn't show the account id.
- **Cover tint**: the saturation-weighted average color of a cover, made more colorful and dimmed to 45% (`cover_tint`). The now-playing cover's tint (`Model.tint`) colors Home; a list page's header uses its own cover's tint (`Model.page_tint`), falling back to the now-playing one.
- **Rounded covers**: Freya clips images to a rounded rect itself (`overflow: Clip` + `corner_radius`); artists are round, other covers get small rounded corners.
- **Pages and navigation**: every main-panel screen (list, album, artist, search, radio) is a `player::Page` pushed onto `nav::History`; back/forward restores it without a request. Album/artist pages take their title from the loaded data, playlists from the clicked row.
- **Row menu**: Freya's `ContextMenu` (right-click or "..."), built per row by `ui::row_menu`; "Add to playlist" is a `SubMenu`; removing from the library asks in a second menu. Actions travel as `Command::RowAction` and re-enter the backend queue as the command they stand for (`OpenList`, `Radio(Some(uri))`). `web::Item` carries the first artist and the album URI for this; the now-playing item from librespot has no album id, so "Go to album" is unavailable for tracks started elsewhere.
- **Exe icon without a build-dependency crate**: `build.rs` calls `rc.exe` directly. `assets/icon.ico` holds PNG-compressed 16–256 px entries generated from `icon-256.png`.
- **Autostart**: the registry `Run` value is the source of truth (the checkbox reads it back after every change). `install.ps1` turns it on only for a first install, so turning it off in the app survives updates.
- **Linux port** (2026-10-20, owner's call: tar.gz + self-update, MPRIS, tray, autostart): Windows-only pieces stay `#[cfg(windows)]` with a `*_linux.rs` counterpart; taskbar buttons and DWM title colors have none. Modifier keys for Ctrl/Shift-click come from the last key event (`track_modifiers`), the Home greeting's hour from `libc::localtime_r`. Updates use the `-linux-x64.tar.gz` asset (binary `slimspot`, set to 0755) and `--wait-pid` polls `/proc/<pid>`. Linux-only direct dependencies `libc`, `rfd`, `zbus` (async-io) were already in the Linux tree with those features. The tray goes through GTK/libayatana-appindicator (Freya's tray feature); untested on a real desktop yet (WSLg has no tray host). Release binaries built on Arch need a recent glibc.
- **`--tray` start**: the window hook queues a hide right after Freya creates and shows the window; media keys and taskbar buttons attach in that hook, since the HWND exists by then.

- **Find in page** (`Ctrl+F` or the magnifier at the right of the action bar, which turns into a pill \"Search in page\" box, a text sort button and a close button; closing clears the filter; on pages with tracks; `Ctrl+L` stays the global search): filter text and sort (page order/title/artist/duration) are applied in the backend (`Command::FilterPage`) to the current page's rows, no request; a new page resets both. "Show more" is hidden while filtering.
- **Playlist reorder**: drag rows of an own playlist (only unfiltered, page order) with a drop marker line; `PUT /playlists/{id}/items` `range_start`/`insert_before`, then the local rows move.
- **Library saves**: albums/artists are saved/followed and removed through the unified `/me/library` (`set_saved`), from the row menu and the page header (Spotify-style "Follow"/"Following" pill on artists, round +/check on albums; state from `is_saved` on open, kept in `Page.saved`).
- **Album header** shows "Album · year · label" (`Page.info`). The Web API dropped Album `label` in Feb 2026, so the label part is normally empty.
- **Playing row**: clicking or hovering the current track pauses/resumes (shows pause while audible) instead of restarting it.
- **Taskbar**: thumbnail toolbar icons are drawn in code (16 px, supersampled), the window is subclassed for `THBN_CLICKED` and re-adds buttons on `TaskbarButtonCreated` (the button is recreated after hiding to the tray). Progress turns yellow (paused) when not playing. Tray tooltip shows "Title - Artist".
- **Updates** (`update.rs`): one check of `/repos/JustEmoBut/SlimSpot/releases/latest` per start, spawned right after the Connect session and before the Web API login (that login can wait for a browser consent forever). A newer `vX.Y.Z` tag with a `-windows-x64.zip` asset shows an "Update to vX" chip in the header; a click goes to the update task over its own channel (`update_rx`), not the command loop, which doesn't run while the Web API login waits (a queued install never ran, 2026-10-05); installing renames the running exe to `SlimSpot.exe.old` (allowed while it runs; overwriting isn't), writes the new one, starts it with `--wait-pid <pid>` and quits. The new process waits (10 s max) for the old one before the single-instance guard, then deletes the `.old`. Verified before the swap: the zip's `.sig` asset (RSA-3072 PKCS#1 v1.5 / SHA-256, `openssl dgst -sign`) against `assets/update-public-key.pem` (`rsa` + `sha2`, both already in the tree via librespot-core/oauth2, no new crates); chosen as RSA while TLS was still native-tls and `ring` wasn't in the tree (owner's call, 2026-10-08). Since the rustls switch `ring` is in the tree too and could verify the same signature, which would drop both direct dependencies; not done. Strict from the first build carrying the key: a release without a valid `.sig` isn't offered/installed. Older builds install unverified, which bootstraps the first signed release. Failures (offline, private repo = 404, bad signature) only go to the log. HTTP via librespot's client (redirects followed by hand), zip via `zip::unzip`: no new crates. Tested 2026-10-05 with a 0.0.9 build against the v0.1.0 release (download, swap, `.old`) and `--wait-pid` separately (the v0.1.0 exe predates it, so it exited as a second instance).
- **Low API usage** (Settings, `settings.json` `low_api`, off by default; quota is per developer account since July 2026, so a second own Client ID doesn't help). When on:
  - `/me/library/contains` answers come from `WebApi.saved` (filled in both modes, read only when on); `set_saved` keeps it current. Saves made in another client show stale until Refresh or restart.
  - The sidebar library comes from `library.json` (per username) when under 6 h old (`LIBRARY_CACHE_SECS`); `refresh_library` rewrites it after every change made here. Only a fully loaded library is written.
  - Home's "New release" lookup (10 requests) runs once per day (`settings.new_release_day`).
  - The Home button reuses Recently played fetched within 60 s (`HOME_TTL`).
  - The refresh button next to "Your Library" (`Command::Refresh`, works in both modes) refetches the library, drops the liked cache, Recently played and the new release, and rechecks the current page's liked marks.
- **Toast on track change** was skipped: it needs an AppUserModelID on the Start shortcut (`install.ps1`).

## Known external constraints (verified against the live API, 2026-10-03)
- Feb/Mar 2026 Dev Mode changes (Spotify migration guide, read 2026-10-08): batch `GET /tracks|albums|artists|episodes|shows`, `/browse/*`, `/artists/{id}/top-tracks`, `/users/{id}*` and `/markets` are gone; `popularity`, `followers`, Album `label`, Show `publisher` and `/me` `country`/`product`/`email` are removed; owner needs Premium; 5 users per new app. July 2026: quota counted per developer account; a quota 429 body carries `"reason": "QUOTA_EXCEEDED"`.
- Development Mode Web API: `search` and `/artists/{id}/albums` reject `limit > 10`; playlists/saved tracks accept 50. Search `offset` works up to 990.
- `/me/player/queue` works (empty: `{"currently_playing":null,"queue":[]}`). `POST /me/player/queue?uri=` answers 404 with no active device and 200 with a non-JSON body on success, so non-GET 2xx bodies that don't parse count as success.
- `POST /me/playlists` creates, `PUT /playlists/{id}` renames, `DELETE /playlists/{id}/followers` removes from the library (all verified live 2026-10-04).
- A deleted app's Client ID can't be told from a live one without a real grant: `/authorize` answers 303 to the login page and `/api/token` with a fake refresh token answers `invalid_grant` for live, deleted and made-up ids alike; only refreshing a real token gives `invalid_client` (checked 2026-10-05).
- A Development Mode app over its quota gets 429 with a Retry-After of hours (65470 s seen 2026-10-05), on its own Client ID, not just the shared one.
- `/me/library/contains` rejects more than 40 URIs (400 "Too many uris requested"). Recently played needs `user-read-recently-played`.
- Playlist edits need `playlist-modify-private`/`-public`; `POST /playlists/{id}/items` `{"uris":[..]}` adds, `DELETE` with `{"items":[{"uri":..}]}` removes (both verified live).
- `/artists/{id}/top-tracks` returns 403 → top tracks come from librespot metadata (`Artist::get` + `Track::get`).
- `/me/tracks/contains` returns 403 → like state and like/unlike use the unified `/me/library` (`contains`, `PUT`, `DELETE`) with `uris=`. `/me/albums`, `/me/following?type=artist` (cursor paging under `artists`) and `/me/player/devices` accept limit 50.
- Changing `WEB_SCOPES` changes the saved grant key, so the next start asks for a browser consent once.
- Spotify-owned/editorial playlists can return 403/404 to third-party apps.
- Spotify doesn't always rotate refresh tokens; librespot-oauth then returns `""` — keep the previous token (`web::refresh`).

## Dependency pins
- `Cargo.lock` pins `vergen` 9.0.6: librespot-core 0.8.0's build script fails with 9.1.0. Don't blanket `cargo update`.
- **TLS is rustls (`rustls-tls-native-roots`), not native-tls** (2026-10-08): with Windows SChannel, the dealer websocket's handshake made Windows download and parse DigiCert's 11.1 MB CRL inside the process (dealer host sends no stapled OCSP), ~32 MB private for the whole run (48.4 -> 17.7 MB idle, same commit). rustls does no online revocation check; roots still come from the Windows store. It brings duplicate rustls 0.22/0.23 (and hyper-/tokio-rustls, rustls-native-certs) from librespot's own tree; accepted by the owner. Exe +2.3 MB.
- **Dependabot alerts on `rustls-webpki` 0.102.8 are dismissed as not used** (2026-10-08, GHSA-82j2-j2ch-gfr8, -pwjx-qhcg-rvj4, -xgp8-3hg3-c2mh, -965h-392x-2mh5): it comes from librespot-core's `hyper-proxy2` 0.1.0 (-> hyper-rustls 0.26 -> rustls 0.22), whose TLS runs only when a proxy matches; librespot sets `Intercept::None` without a proxy and SlimSpot never sets one, and nothing feeds rustls CRLs. Our connections use rustls 0.23 / webpki 0.103.15 (patched). 0.102 has no fixed release; recheck when librespot is upgraded or if a proxy setting is ever added.
- **Dependabot alert on `glib` 0.18.5 is dismissed as not used** (2026-10-20, GHSA-wrw7-89jp-8q8g, alert #5): it comes in through Freya's GTK tray stack (Linux only). The unsound `VariantStrIter` is reachable only via `glib::Variant::array_iter_str`, which no crate in the tree calls (only glib's own tests). gtk 0.18 pins glib 0.18, so no patched version is reachable; recheck when Freya moves off gtk 0.18.
- `librespot`/`librespot-oauth` =0.8.0, `freya` =0.5.0-rc.10 (a release candidate: its API still changes), `windows` =0.62.2 (already pulled in by cpal/winit; only features added).
- `Cargo.lock` pins `prettyplease` 0.3.0: Freya's Skia build runs `bindgen` 0.73, which needs syn 3, and the resolver had picked 0.2.37 (2026-10-20).
- Prefer crates already in `Cargo.lock`; check with `cargo tree -d` that an addition doesn't add a second version.
